Why brands call us

Stock is paid for before anyone says yes.

A brand commits to a season, pays the factory, and finds out later who the product fits. Customers order two sizes and return one. The cost shows up as markdowns, freight and landfill risk.

Germany is the highest-returns market in Europe. Bamberg's return research group forecasts about 550 million return parcels for 2025, and nearly one in four online parcels comes back in full or in part.1 The EHI fashion study found that 24.5% of surveyed fashion shops see return rates between 36 and 50%.6

Fit is the reason people give. In Deloitte's April 2026 survey of 1,000 German consumers, about two thirds of those who returned items said the item did not fit, and 69% said they want to return less.2 Only 29% have used a size advisor so far.

The other end of the chain has its own pressure. The EU ban on destroying unsold clothing, accessories and footwear has applied to large companies since 19 July 2026. Medium-sized companies follow in 2030, and micro and small firms are exempt.5 The Digital Product Passport registry went live on 20 July 2026, and mandatory textile passports are not expected before about 2028.7

SELFWEAR® starts from the other direction. Learn what each customer wants and how they are built, sell it, and release production only for what has been sold.

Capture the body once, from a phone. Reuse the profile on every product.

Live for foot capture

Production Engine API

Fit data goes in. Machine-ready files come out.

Live for custom insoles

Garment patterns and tech packs are in development. Terms for in-development services are set with each design partner.

Customer measurements and fit metadata arrive as an API call. The engine builds a parametric model and returns production files: print-ready G-code for insoles today, and CAD, tech packs and cutting patterns as the garment modules mature. A typical style goes through three to five physical sample rounds before release,11 and this service targets that loop.

  • Parametric model per customer, generated from the fit profile.
  • Output for your factory or a partner, in the format that machine reads.
  • Fit outcomes feed back to retrain the model, so the next order starts better.
  • Every job carries a job token, so a file can be traced from request to delivery.

Send each production file to a factory that can make it, and start fulfillment automatically.

In build

Data and updates

Names and contacts stay on your server.

Body measurements and visuals are sensitive. Under the GDPR, biometric data is special-category data when it is processed to identify a person, and explicit consent is the realistic route.8 We built the system around that: the SELFWEAR server never receives names, contacts or addresses.

Each service ships as its own container release. Deploys run through GitHub Actions with automated tests, a health check that must report the new version, and automatic rollback if it does not. A deploy key can run four actions only: deploy, platform sync, rollback and status.

Updates to a service are built to reach every client server that runs it through the same tested path, so nobody logs in by hand to patch your system.
